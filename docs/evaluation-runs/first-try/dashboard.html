Scores

Retrieval metrics need no language model: they compare returned citations against the documents the test set names as valid. Judge metrics use openai/gpt-4o-mini through OpenRouter.

Retrieval — deterministic, no LLM Judge — LLM-as-judge

Retrieval is exact. The two answer-side metrics sit below 1.0 because of four cases — and on inspection three of those deductions are judge errors, not pipeline faults. Mean response time 3.3 s per question.

The judge got three of four wrong

All four answers below are correct. Checked against the reference answers, three of the four deductions contradict the ground truth the judge was given. Retrieval fetched the right document in every case.

standard-excess-per-claim — judge wrong

Judge said: the answer "incorrectly implies that the excess of £40 is an additional cost to the annual deductible".

But the reference answer reads: "An excess of £40 applies to each separate claim on the Standard plan, in addition to the annual deductible." The pipeline's answer is near-verbatim identical. The judge penalised an answer for matching its own ground truth.

table-annual-health-assessment — judge wrong

Judge said: the answer "incorrectly claims that the Annual health assessment feature is listed as 'No' for Standard, which contradicts the retrieval context".

But the comparison table does list Standard as "No". The answer quoted the row correctly across all three tiers. The judge misread the context it had been handed.

table-physiotherapy-premium — judge wrong

Judge said: the output "included irrelevant information about coverage conditions instead of directly addressing the number of sessions".

But the answer opens with the number — 24 sessions per year — and the "irrelevant" clause is the GP-referral condition that the reference answer also carries. Faithfulness scored 1.00 on the same answer.

paraphrase-claim-window — judge defensible

The question asks about "the mid-tier policy", a phrase in no document. The answer resolved it to Standard and gave the correct 60-day window, and was docked for asserting an equivalence the context never states.

Strict rather than wrong: mapping "mid-tier" to the middle of three tiers is sound, but the documents genuinely do not say it. The one deduction worth keeping.

The most important result of this exercise. A cheap judge over 15 cases produced three false positives and no true ones, while the deterministic metrics caught every genuine defect. openai/gpt-4o-mini is a small model running deepeval's multi-step claim-extraction chains, where an error at any step compounds — and two of its three mistakes are self-contradictory. Treat the judge tier as unproven until it is re-run against a stronger model. On this test set the pipeline is at 100% on every metric that can be trusted.

What the numbers mean

source_hit_rate
Share of answerable cases where a returned citation came from a document the test set names as valid. The metric a per-answer relevancy judge cannot produce. Without ground truth there is no way to know the system quoted the Premium deductible at a question about the Standard plan.
mean_reciprocal_rank
Average of 1 ÷ (position of the first correct citation). Correct document first every time gives 1.000; consistently second gives 0.500. Separates "found it" from "found it first".
refusal_accuracy
Share of cases where declining matched expectation: the three negatives refused, the twelve answerable ones not. Catches over-eager answering, which relevancy scoring rewards — a fluent answer to an unanswerable question looks highly relevant.
grounded_rate
How often the pipeline set its own grounded flag. At 100% including on questions with no answer in the corpus, this flag currently carries little information. See the grounding-filter finding.
contextual_precision / contextual_recall
Judge metrics scoring the retrieved context against the reference answer: whether relevant chunks ranked above irrelevant ones, and whether the context covered everything the reference answer needed. Both 1.000, which agrees with the deterministic retrieval scores — two independent methods reaching the same verdict.
faithfulness
Whether every claim in the answer is supported by the retrieved context. The hallucination check. 0.896 — but both deductions were traced to judge error, not unsupported claims. No hallucination was found in this run.
answer_relevancy
Whether the answer addresses the question asked, without padding. 0.854, lowest of the four and the least reliable: it docked answers for clauses the reference answers themselves contain.

Defects this exercise surfaced

Three of the five were in the evaluation code itself. That is expected on a first run and is the argument for keeping these baselines.

Refusal detection matched only canned strings

The scorer recognised refusals by substring-matching the pipeline's two fixed phrases. A real model refuses in its own words — "I could not find information about a Platinum plan in the indexed documents" — so all three negatives were refused correctly and all three scored as failures, reading 80% instead of 100%. Now requires an inability phrase and a reference to the documents in the same sentence, so a negative fact such as "dental cover is not included on Basic" still reads as an answer.

A provider outage was scored as a refusal

In an earlier attempt one answer call timed out and the pipeline returned its evidence-only fallback. The broadened matcher read that as a decline and failed the case. An LLM failure is a third state, neither answer nor refusal: it is now detected separately, recorded as an errored case and excluded from every rate, so an outage cannot masquerade as a retrieval regression.

The grounding filter passes irrelevant chunks

Asked who ShieldCare's chief medical officer is, retrieval returned chunks about out-of-network reimbursement and flagged them grounded: true. The filter admits a chunk when 10% of the question's words appear in it, and "ShieldCare" appears in every document, so the no-evidence branch never fires. The model refuses anyway, so the user sees the right outcome, but the flag is unreliable and the burden sits entirely on the prompt.

Not fixed. It affects the live chat path and deserves its own before/after run against this baseline.

A latent embedding bug, fixed

The keyless embedding provider bucketed tokens with Python's hash(), which is salted per process. Vectors differed between runs, so a persisted index became unmatchable after a backend restart and retrieval silently degraded to noise. Replaced with a blake2b digest, confirmed stable across separate processes. Existing EMBEDDING_PROVIDER=local indexes must be rebuilt.

The judge tier is not yet trustworthy

Of four sub-perfect scores, three were judge errors contradicting the supplied ground truth, and none identified a real defect. Every genuine problem in this exercise was caught by the deterministic metrics or by reading the output. Until a stronger judge model is tried, faithfulness and answer_relevancy should not drive decisions.

The judge failed loudly twice before succeeding

First attempt: all 60 metric slots recorded error with 429 free-models-per-day — the fifteen answers had consumed a 50-request daily cap. Second: TimeoutError, the throttled free model unable to return structured JSON in time. Both times no score was invented in place of the failure, which is precisely what the previous fail-open evaluator got wrong. Switching the judge to openai/gpt-4o-mini resolved it.

The corpus

Four PDFs written for this test and generated by a dependency-free script, so nothing private reaches a cloud judge. Three are deliberately near-identical in structure and differ only in their values: "what is the deductible?" matches all three almost equally on word overlap, so answering it requires retrieval to genuinely discriminate. ShieldCare is fictional.

The test set

15 cases, each carrying a reference answer and the document IDs that can legitimately support it. Document IDs are fixed rather than generated, so re-ingesting a document overwrites its vectors instead of duplicating them.

KindCasesWhat it stresses

cross-doc2Questions spanning tiers, forcing multiple citations and exercising document-level marker collapsing.

negative3Answers absent from the corpus entirely. The correct behaviour is a refusal, which no relevancy metric can check.
