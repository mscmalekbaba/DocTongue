# Evaluation run — first try

The first end-to-end runs of the offline evaluation harness, kept as a baseline
to compare later runs against. Dated 31 October 2026.

## Contents

| Path | What it is |
|---|---|
| `corpus/` | The four fixture PDFs the questions are written against, exactly as indexed |
| `testset.json` | The 15 ground-truthed cases, copied from `backend/app/evaluation/testset.json` |
| `*.json` | Result documents, one per run, named by run id |
| `dashboard.html` | Visual summary of these results |

The PDFs are generated by
[`generate_corpus.py`](../../../backend/app/evaluation/corpus/generate_corpus.py)
and are copied here so this folder stays readable even after the generator
changes. They are fictional: ShieldCare is not a real insurer.

## Results

Final run: `20261031T203622Z-1feba7`, the first in which every metric completed.
The earlier `20261031T201104Z-97950f` is kept because its two failures are
instructive.

### Retrieval — deterministic, no LLM

| Metric | Value |
|---|---|
| Source hit rate | **100%** (12 of 12 answerable) |
| Mean reciprocal rank | **1.000** (correct document always first) |
| Refusal accuracy | **100%** (3 of 3 negatives) |
| Grounded rate | 100% |
| Mean response time | 3.33 s |

### Judge — `openai/gpt-4o-mini` via OpenRouter

| Metric | Value |
|---|---|
| Contextual precision | **1.000** |
| Contextual recall | **1.000** |
| Faithfulness | 0.896 |
| Answer relevancy | 0.854 |

48 of 48 applicable metrics scored; 12 skipped by design (the three negative
cases, where contextual recall against a refusal is meaningless).

Both contextual metrics agreeing with the deterministic retrieval scores is
worth noting: two independent methods reaching the same verdict.

### The four sub-perfect judge scores are judge errors, not pipeline faults

Checked against the actual answers, three of the four deductions are wrong — the
judge contradicted the ground truth it was given.

| Case | Judge's claim | Verdict |
|---|---|---|
| `standard-excess-per-claim` | "incorrectly implies the £40 excess is additional to the annual deductible" | **Judge wrong.** The reference answer says "in addition to the annual deductible" in near-identical wording. The judge penalised an answer for matching the ground truth. |
| `table-annual-health-assessment` | "incorrectly claims the feature is listed as 'No' for Standard, contradicting the context" | **Judge wrong.** The comparison table does list Standard as No. The judge misread its own retrieved context. |
| `table-physiotherapy-premium` | "padded with irrelevant coverage conditions" | **Judge wrong.** The "padding" is the GP-referral clause, which the reference answer also contains. |
| `paraphrase-claim-window` | "assumes Standard is the mid-tier plan, which the context never states" | **Defensible.** The documents never use "mid-tier". The inference is sound but genuinely unstated. |

All four answers are correct. **On this test set the pipeline scores 100% on
every metric that can be trusted**, and `faithfulness` 0.896 / `answer_relevancy`
0.854 are judge noise.

The cause is visible in the configuration: `openai/gpt-4o-mini` is a small model
running deepeval's multi-step claim-extraction chains, where an error at any step
compounds. Two of the three mistakes are self-contradictory.

**This is the most important finding of the exercise.** A cheap judge over 15
cases produced three false positives and zero true ones, while the deterministic
metrics caught every genuine defect. Treat the judge tier as unproven until it is
re-run against a stronger model; the deterministic tier is the signal.

### Keyless comparison

With `LLM_PROVIDER=stub` and `EMBEDDING_PROVIDER=local` the same test set runs
with no key, no network and no cost at 0.004 s per case: 91.67% hit rate, 0.833
MRR, judge skipped. Word-count embeddings cannot reach the comparison table and
rank the correct document second twice. That mode proves the harness works and
suits CI; it does not judge pipeline quality.

## Defects this exercise surfaced

Three of five were in the evaluation code itself — expected on a first run, and
the reason for keeping this baseline.

**Refusal detection matched only canned strings.** The scorer recognised refusals
by substring-matching the pipeline's two fixed phrases, but a real model refuses
in its own words ("I could not find information about a Platinum plan in the
indexed documents"). All three negatives were refused correctly and all three
scored as failures, reading 80% instead of 100%. `is_refusal()` now requires an
inability phrase *and* a reference to the documents in the same sentence, so a
negative fact ("dental cover is not included on Basic") still reads as an answer.

**A provider outage was scored as a refusal.** In run `...97950f` an answer call
timed out and the pipeline returned its evidence-only fallback; the broadened
matcher read that as a decline and failed the case. An LLM failure is a third
state, neither answer nor refusal — now detected separately, recorded as an
errored case and excluded from every rate, so an outage cannot masquerade as a
retrieval regression.

**The grounding filter passes irrelevant chunks.** Asked who ShieldCare's chief
medical officer is, retrieval returned chunks about out-of-network reimbursement
and flagged them `grounded: true`. The filter admits a chunk when 10% of the
question's words appear in it, and "ShieldCare" appears in every document, so the
no-evidence branch never fires. The model refuses anyway, so the user sees the
right outcome, but the flag is unreliable. **Not fixed** — it affects the live
chat path and deserves its own before/after run against this baseline.

**A latent embedding bug.** The keyless provider bucketed tokens with Python's
`hash()`, which is salted per process, so a persisted index became unmatchable
after a backend restart and retrieval silently degraded to noise. Replaced with a
`blake2b` digest. Any existing `EMBEDDING_PROVIDER=local` index must be rebuilt:
delete `backend/data/chroma` and re-upload.

**The judge failed loudly twice before succeeding.** First `429
free-models-per-day` — the fifteen answers had consumed a 50-request daily cap.
Then `TimeoutError`, the throttled free model unable to return structured JSON in
time. Both times no score was invented in place of the failure, which is what the
previous fail-open evaluator got wrong. The judge needs a model that reliably
returns JSON under load; `nvidia/nemotron-3.5-super-vl:free` does not.

## Reproducing

From `backend`:

```bash
python -m app.evaluation.run                        # deterministic metrics, no API key
EVAL_JUDGE_ENABLED=1 python -m app.evaluation.run   # adds the four judge metrics
```

Neither local interpreter carries the project dependencies, so these runs were
executed in a container:

```bash
docker run --rm -v "$PWD/backend:/app" -w /app python:3.12-slim \
  bash -c "pip install -e '.[dev]' && python -m app.evaluation.run"
```

Results are written to `EVAL_RESULTS_DIR` (default `backend/data/evaluations`).
Every result snapshots `retrieval_k`, `chunk_size`, `chunk_overlap` and the
provider/model pair, because without that two runs are not comparable.
